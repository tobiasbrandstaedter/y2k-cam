# ADR-003: PWA plumbing

Status: accepted, 2026-11-13

## Context

UX-7 and UX-8 ask for an app that opens from the home screen and works with no
network after the first load. ADR-001 left the manifest and service worker
approach open. The build output has hashed file names, so a hand written
service worker would need its own build step to learn what to precache.

## Decision

`vite-plugin-pwa` (dev dependency, generates a Workbox service worker) with:

- `registerType: 'prompt'`: a new service worker waits until every tab of the
  app is closed and takes over on the next launch. No `skipWaiting`, no
  reload prompt, no code swap under a running edit (QA-8).
- Precache of all JS, CSS, HTML, PNG and woff2 in the build. Nothing is fetched
  at runtime from anywhere else, so no runtime caching rules (QA-7).
- Manifest written by the plugin from the config, so `start_url` and `scope`
  follow the Vite `base` and work both at `/` and under the Pages prefix.
- Apple meta tags and `apple-touch-icon` in `index.html`, because iOS 17 reads
  those for the home screen icon and title, not the manifest icons
  (WebKit blog, "Web Apps in iOS 17", 2023).

Icons are generated by a throwaway script, no design tool in the loop.

## Alternatives

- Hand written service worker with a manual asset list: breaks on every build
  because of the hashes, or needs a build plugin, which is what the chosen
  plugin already is.
- `registerType: 'autoUpdate'`: reloads clients when a new version arrives.
  Rejected, it would drop an edit in progress.
- No service worker, rely on the HTTP cache: Safari evicts it freely and
  the installed app would show the offline error page.

## Unverified on iOS

No iPhone in this project. Standalone launch, offline start from the home
screen and the 7 day storage eviction for installed PWAs are taken from the
WebKit release notes for iOS 17 and must be checked on a device.
